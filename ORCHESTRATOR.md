# ORCHESTRATOR.md — Nuke Codex Panel

Repo brief
- Foundry Nuke agent panel (`~/.nuke/nuke-codex-panel`): dockable PySide6 chat client for Codex / Claude Code / pi / OMP / opencode harnesses. Pure-python package (`nuke_codex_panel/`), Python 3.11 under Nuke 17.1; no build step; symlinked into `~/.nuke` and registered via `menu.py` → `panel.py` → `ui/panel_widget.py`.
- Runtime: harnesses are subprocesses speaking JSONL (codex app-server, `claude -p stream-json`, pi/omp `--mode rpc`, opencode serve+SSE). Nuke MCP sidecar (`harnesses/nuke_mcp.py` + `mcp_server/server.py`) exposes `execute_python` / `get_nuke_context` / `capture_nuke_screenshot` through one application-owned Qt TCP bridge (`bridge/lifecycle.py` + `bridge/server.py`). Its authenticated discovery record is `$XDG_RUNTIME_DIR/nuke-codex-panel-<uid>/session-<pid>-<hex>.json`; panes share that bridge and never stop it.
- Tests: smoke scripts run inside a live Nuke GUI (they `import PySide6`, which only exists in Nuke's process): `tests/chat_render_smoke.py`, `tests/chat_scroll_smoke.py` (added 8fd9ce3), `tests/*_smoke.py`, plus pytest-style `tests/test_*.py`. CI = N/A; verification is in-Nuke.
- Env: Nuke usually launched via `ghostty -e /opt/Nuke17.1v1/Nuke17.1 --nukex` from Omarchy desktop entry `~/.local/share/applications/nuke17-nukex.desktop`. Machine facts: `claude` lives ONLY at `~/.local/share/mise/shims/claude` (mise-managed; NOT in npm-global). `codex`/`pi`/`omp`/`opencode` at `~/.npm-global/bin`. MCP access to the live panel: pi `nuke` MCP server (execute_python) — requires a valid bridge discovery file.

Decision log (append-only)
- 2026-10-28 CPU storm root cause + fix: panel open during ANY streaming chat pinned Nuke's main thread at 100% (node graph pan/zoom, viewer playback starve; Nuke can crash). Cause: `BubbleText.heightForWidth()` mutated `document.setTextWidth()` — layout-system width queries relayouted the document, `documentSizeChanged` → `_fit_height` → `setMinimumHeight` → layout invalidation → `heightForWidth` again: self-sustaining loop, re-kicked by every 60ms streaming render. Fix: `heightForWidth` is now a pure query returning cached `_fitted_height`; document width set only in `_fit_height` from `viewport().width()` (single width source → converges). Verified in a clean repro Nuke (no user plugins): same 8s stream stress went from 99.9% CPU + timer starvation + Nuke death → bounded CPU, returns to idle after stream, 138 bubbles 0 clipped, chat_render_smoke PASS.
- 2026-10-28 Follow-on exposed by the fix: bottom-pinning used to "work" partly because the storm kept re-emitting height_changed after the scrollbar caught up. Pin now arms `_pin_pending` and is consumed on `rangeChanged` (scrollbar maximum was stale at height_changed time). chat_scroll_smoke was wall-time dependent (only passed because the stormy code was slow) → pump() now does QtTest.qWait(10). Pin fix compile-OK, final live smoke run PENDING user approval for a Nuke window.
- 2026-10-28 Bridge hardening: `_read_socket` guard against RuntimeError on a deleted QTcpSocket (disconnect mid-request killed the handler; seen in repro log at /tmp/ncp_nuke.log). Compile-verified.
- 2026-10-28 Repro harness (reusable, no windows without user OK): NUKE_PATH overlay /tmp/ncp-overlay (menu.py seeds ChatStore for cwd /tmp/ncp-proj, opens panel via nukescripts.panels.restorePanel), stress = 160 feed_timer ticks at 50ms into chatView, event spy via app.installEventFilter, results to /tmp/ncp_spy_results.json. Panel harness comes from QSettings (pi on this machine), chat stress is harness-agnostic.
- 2026-10-28 Claude deadlock fix (8fd9ce3): claude's stream-json emits `init` only when the FIRST user message is processed; panel gated Send on init → deadlock. ClaudeClient now announces static KNOWN_MODELS and readiness at process start (`_on_started`); send triggers init. Verified live: pi→claude switch, send, stream, turn completes.
- 2026-10-28 Scroll pinning (8fd9ce3): BubbleText refit moved from `contentsChanged` (pre-layout `document.size()` → height wobble → chat jumping) to `documentLayout().documentSizeChanged` (post-layout). Bottom re-pin only when user is within 40px of the bottom; `_render_section` no longer scrolls (height_changed signal → `_stick_if_pinned`). Verified: `tests/chat_scroll_smoke.py` (constrained viewport via `setFixedSize` — top-level windows auto-grow and defeat the test).
- 2026-10-28 Rediscovery of binary resolution: `resolve_binary` now also probes per-user dirs (`~/.local/share/mise/shims`, `~/.npm-global/bin`, `~/.local/bin`, `~/.bin`) after PATH — desktop-launched Nuke may have a minimal PATH (README already warns; user hit this with Claude before mise shims were on PATH).
- 2026-10-28 Bridge discovery filenames are per-panel-instance (`session-<pid>-<hex>.json`) + stale-prune; a shared `session-<pid>.json` let one panel's `stop()` delete the other's record, bricking the MCP sidecar (also broke the orchestrator's own MCP link mid-session).
- 2026-10-28 Teardown noise: `errorOccurred(Crashed)` suppressed when the QProcess already exited (NotRunning); `finished()` reports real exits.
- 2026-10-28 wlroots capture (user's WIP, committed fb4f784): `capture/widgets.py` adds `_grim_grab` (Hyprland/Sway via `grim`, Spectacle-style 12s timeout/kill), used when `XDG_SESSION_TYPE == wayland` and KDE Spectacle does not apply.
- 2026-10-28 Unified MCP merged onto main `7915e3b`: application-owned bridge lifetime supersedes the per-pane ownership above; UUID discovery filenames and disconnect hardening remain. All five harnesses use `harnesses/nuke_mcp.py` and pin their own Nuke session. pi/omp inherit the pin through process environment, leaving global MCP config unpinned. Hiding or closing a pane revokes Trusted Python without stopping external MCP access.
- 2026-10-28 Merge verification: 20 pytest tests passed inside Nuke 17.1v1; panel persistence and real shared-bridge smokes passed. Real sidecars generated from all five harness configurations plus external Codex/OpenCode registrations reached the same marker node; an invalid explicit pin failed closed. No model turns were run.
